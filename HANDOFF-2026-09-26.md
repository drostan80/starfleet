## 2. The user's rules (the design — apply these, don't re-derive)

| Area | Rule |
|---|---|
| Identity | Absolute episode order is the spine (Memory Alpha/AniDB). LCARS season number ≠ TVDB season number. Identity only from ID crosswalks (Fribb, Wikidata, Anime-Lists), never title search; no match → unlinked + review. Missing evidence never clears a link. |
| Lists | **LCARS is the hub and source of truth.** An edit on AniList or MAL goes into LCARS, then to the other list; an LCARS change goes to both. Decided by `list_baseline` (which side changed since last agreement), never "the list always wins". AniList and MAL mirror each other through LCARS. A MAL id follows AniList's Fribb pairing. |
| Auto-created seasons | Never pushed anywhere (AniList, MAL, Sonarr): `season.list_sync = 0`. Status: not finished airing → `planned`; otherwise previous season watching/completed/paused → `paused`, dropped → `dropped`. User acting on a season (status, score, watching an episode, rewatch) or adding it on a list turns sync on. |
| Sonarr | LCARS drives Sonarr: LCARS drop/pause → unmonitor, resume → re-monitor, LCARS add → Sonarr add. A series **added in Sonarr** is created in LCARS. **Changing monitoring in Sonarr never changes LCARS** (user flip-flopped before; final 09-26). |
| Air dates | Earliest real date wins across sources; the same source may correct its own date either way (reschedules); `manual` is absolute; gap-fillers (TVmaze/AniDB/Syoboi fill) only fill NULL. MAL is not an air-date source. Open question: see §5. |
| Purges | Order Sonarr → LCARS → lists. Local purge for junk that shares real ids (never `confirmHardDelete`). |
| Orphaned FK rows | Delete. |
| Scores | AniList's score is accepted (score_sync); not part of the hub baseline. |
