## 3. Code changes (what, where, why)

### Identity from absolute order (v0.2.56–58) — the Slime bug
Symptom: Slime S04E24 and S05E24 both "airing next Friday". Cause: LCARS split
TVDB S2 into LCARS S2+S3, so every later LCARS season sat one ahead of TVDB's,
and several writers treated "LCARS season N" as "TVDB season N".

- `src/lcars/sonarr_match.py` (new): the one place a Sonarr episode is matched to
  an LCARS row, in this order: captured Sonarr coords, then `absoluteEpisodeNumber`,
  then display numbering (only where nothing shows divergence). Captures
  `sonarr_season/episode`. Merge losers are not siblings. New episodes are routed
  by abs range / established season offset.
- Used by `metadata._fetch_sonarr` (both paths), `local_audit`, and the
  `availability` fallback.
- `anidb.derive_episode_mappings`: Anime-Lists gets real TVDB coords. The
  air-date arbiter only locks against an independent date (not AniList-written).
  A confirmed AniDB episode is never shared with a guessed one (Bookworm). A
  manual season link beats a stale community list (Chitose).
- `season_mapping.reconcile_season` / `_derive_ids`: identity from Memory Alpha
  (season's AniDB entry → Fribb), then TVDB coords; episode-less seasons use
  Fribb *position* (the model they were created with); strict TVDB-season match
  (no "one entry → every season" shortcut); **no candidate never clears a stored
  link**.
- `metadata._reconcile_air_dates`: skips a season whose AniList schedule is
  >60 days (median, ≥3 eps) from Sonarr's raw dates.
- `season_ranges.seed_episode_external_ids`: derived per-episode ids follow
  their source (stale rows dropped).

### ops / scheduling
- ops waits for LCARS to answer before starting its loops (v0.2.57); the
  availability loop retries in 60 s instead of 3600 s after a failed check.
- **Monthly tier persisted** (v0.2.59/60): new table `ops_tier_checkpoint`
  (migration `a3c9e1f40b27`), `opsTierDue` / `markOpsTierCompleted`. ops checks
  hourly and runs the full-library pass only when a month has passed. Before
  this, the pass either never ran (it lost the startup race, then slept 30 days)
  or ran on every deploy.

### MAL / scores
- `setSeasonMapping`: an absent or unchanged (pre-filled) MAL id follows Fribb's
  pairing for the AniList id; a deliberately changed one is kept.
- `pollScoreSync` returned camelCase keys → always errored after the sweep ran. Fixed.
- `score_sync.check_mal_score_drift`: consistent when |MAL×2 − LCARS| ≤ 1
  (13.0 = 6.5 on MAL; 6 or 7 are both right).
- `fribb.py`: index caches were keyed on `id(dataset)` alone (id reuse → stale
  index). Now `is`-checked. Helpers `mal_for_anilist`, `anilist_ids_for_mal`.

### Linking (v0.2.62) — root cause of the wrong-series pattern
- `shows._resolve_arr_candidate`: with no `tvdbId` it took Sonarr's **first
  free-text title result** and added + linked it. Now the TVDB id comes from the
  input or the ID crosswalk (`_resolve_tvdb_for_sequel`: Fribb from AniList/MAL,
  Wikidata from TMDB/IMDb). With neither, the show is added **unlinked** and a
  `tvdb_link` review opens.
- `service_presence`: presence stays fuzzy, but a Sonarr/Radarr **link** is
  written only when the catalog's tvdbId/tmdbId equals the show's.

### UI
- Global search: `.search-overlay[hidden]{display:none}` (author `display:flex`
  beat the UA `[hidden]` rule); Escape closes from anywhere; the "esc" chip is a
  real button. Verified in headless Firefox (old code fails, new passes).

## 6. Mistakes made this session (so they aren't repeated)

- Told the user CI passed when it had failed: the background check's exit code
  came from `echo`, not CI. **Rule:** read job conclusions.
- Declared the white-icon bug fixed earlier (v0.2.52) without a browser check. It
  isn't fixed. **Rule:** UI fixes are done only when the user sees them fixed.
- A "read-only" verification script called `reconcile_season`, which commits per
  season — it wrote the real Tantei ids onto the junk show. **Rule:** verification
  runs on a DB copy.
- Purged Milky Holmes from LCARS and the lists while the series stayed in Sonarr
  → the untracked sweep recreated it and re-pushed the entries. **Rule:** Sonarr →
  LCARS → lists (memory `junk-purge-order-sonarr-first`).
- The v0.2.57 startup-wait change unintentionally made the monthly full pass run
  on every deploy. **Rule:** a change that alters *when* a job runs needs its own
  review.
